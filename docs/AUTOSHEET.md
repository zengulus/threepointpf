# Autosheet coverage and next frontier

## Source boundary

Input: `INGEST THIS - Pathfinder Autosheet (v6.2.1).xlsx`, SHA-256 `bf1fe035fe70688b0c7406308252a6c10013d2ce3220c7f21241fb55233d71b8`.

`scripts/import-autosheet.mjs` validates with the current local schema, without depending on stale build output. It reads cached values and never evaluates workbook expressions. Generated source-only `.js` bridges support Deno alongside package builds. `--check` compares every expected byte and fails on missing/stale files.

The report inventories all eight sheets (including hidden sheets), imported rows, normalizations/warnings, unsupported regions, and failures. A malformed known layout fails import before replacing output. The workbook is a versioned source snapshot, not an authority for silently resolving PF1e/3.5/third-party differences.

## Imported and operational

- **Class Charts, rows 3–295, 312–492 and 518–632:** all 259 parseable chassis rows, 27 standard prepared/spontaneous PF1e casting templates, nine Psionics charts with the workbook's ability-and-level bonus power-point lookup, and 17 FFd20 magic-point/spells-known progressions. The 89 prestige charts have explicit cumulative rows and maximum levels. Formula semantics remain in the engine, not class-name switches.
- **Class Skills, rows 1–278:** 257 scoped joins, 42 classic skill definitions, and 12 source-backed Consolidated Skills with ability, training, armor-check, and per-class metadata. Joining uses section plus normalized name. Three prose-only skill metadata supplements are marked in the report; alternate skill markers remain separate from classic membership.
- **Welcome Page, P6 skill modes:** Background Skills is the workbook default; Ultimate Psionics + Background Skills uses the same two-rank background allowance with its psionic class-skill facts. Consolidated switches to the workbook’s 12 grouped skills, uses `max(1, floor((class skill points + INT modifier) / 2))` per level, and reads separate consolidated class-skill markers. Classic Skills disables the background-rank allowance.
- **Formula References, rows 149–206:** 45 physical armor/shield chassis. Penalty magnitudes become negative contributions; blank Max Dex is unlimited, zero is a cap. Column I is weight category, never pounds. Spell-failure chance is metadata only. Medium/heavy armor reduces land speed; armor/shield effects respect AC contexts.
- **Formula References, rows 208–232:** compatible materials add their workbook AC, maximum Dexterity, armor-check penalty, and arcane spell-failure adjustments to an armor/shield item. Compatibility follows the source chassis' material-type column; incompatible selections are flagged. Special-note text is shown on the item, but its DR, resistance, initiative, and other rule text is not yet resolved into mechanics.
- **Formula References, C/F/I/L/X/AA45:61:** 60 ability-based attack profiles covering ordinary, two-handed, off-hand, ranged, thrown/composite, finesse/agile, single and natural attacks, including STR/DEX/WIS variants. A closed label grammar emits declarative ability, multiplier, mode, tag, iteration and Haste-eligibility fields. Secondary natural attacks default to −5; explicit attack adjustment supports separately qualified alternatives. Prerequisites in descriptions are not granted automatically.
- **Formula References, rows 114–134:** slow/medium/fast XP charts for levels 1–20. Level-one dashes become zero. Exact thresholds and one-point-below boundaries are tested for every track. XP never edits advancement or invents epic thresholds.
- **Formula References, rows 28–34:** five optional age-category ability adjustments, exclusive within one data-defined group. These are not racial age thresholds or the Young Creature template.
- **Formula References, rows 237–268:** numeric AC, ability, save, attack, damage, skill, caster-level and movement effects are imported as toggleable conditions. Text-only action restrictions remain descriptive because the workbook has no executable action-state formulas for them.
- **Formula References, row 265:** optional Unchained Wound System thresholds are available per character. Below 75%, 50% and 25% maximum HP, AC, saves, attacks, skills and caster levels take −1, −2 and −3 respectively. The option defaults off, matching the workbook’s inactive setting; damage is not modified.
- **Welcome Page, P8:** optional minimum 4 + INT skill points per level is available in the character rules. When enabled, it raises the winning class skill-point chassis to at least 4 before adding the Intelligence modifier for creation and level-up allocations. It defaults off, matching the workbook.
- **Welcome Page, P6 background rows:** each level grants 2 additional ranks for Appraise, Handle Animal, Knowledge Engineering/Geography/History/Nobility, Linguistics, Sleight of Hand, and Perform. Unused background ranks cannot be reassigned to ordinary skills.
- **Main Sheet, rows 101–106 and 115:** Power Attack, Combat Expertise, Deadly Aim, Heroism, Haste, Rapid Shot and one negative-level toggle use ordinary Feature/Effect data. Negative levels apply the workbook's −1 roll/caster-level and −5 HP penalties.
- **Spells, Spheres and other stuff:** standard casting and specialized systems use character-owned sources. Spheres of Power derives spell points from class level and key ability, caster level, and `10 + floor(CL/2) + ability`; Spheres of Might uses `10 + floor(effective BAB/2) + ability` with its own effective-BAB adjustment; Veilweaving derives the workbook's level-banded essence pool. Maneuver DCs use tier plus key ability. Manual resource adjustments support workbook fields such as FFd20 MP Stat, and individual entries track separate per-day uses for spell-like abilities. These systems keep authored entries and resource use with the character.
- **Spell-like ability uses:** character abilities can be tagged as 1/day, 3/day, at-will, constant, or custom daily use, linked to a spell catalog reference, and given daily counters where limited. Limited activated abilities consume a use; a refresh action resets their counter. The ability action runs its authored rollable effects. The linked spell is a reference; its spell effects are not automatically executed.
- **Touch spell attacks:** catalog or character-local spells can resolve melee-touch and ranged-touch attack rolls using BAB, the matching ability modifier, size, contextual attack effects, and the attack outcome policy. A character-local spell can author either touch attack with its damage expression.
- **Spell healing rolls:** healing spells roll authored dice and can add an authored flat bonus or a caster-level bonus with a cap. The sample Cure Light Wounds now rolls `1d8 + min(caster level, 5)`; applying the rolled healing to HP remains a separate player action.
- **Size:** all nine categories, relative shifts, clamping, nonlinear AC/attack/CMB/CMD modifiers, Tiny-or-smaller Dexterity CMB, Fly/Stealth adjustments and source chains. Size does not arbitrarily change authored base speed.
- **PRD supplements:** six starter weapons, a steel shield, three magic items, tower-shield attack penalty and agile-armor Climb exceptions. These are separately sourced; their workbook chassis remain independently inspectable.

Class features are not inferred where the source supplies only a chassis. Custom classes declare level-gated names/notes and explicit effects. Effects unlock at global class level once and disappear when advancement is undone. The character lifecycle can propose the same imported or local progression, including a monster-style progression, without a separate official-versus-homebrew engine. This supports arbitrary authored classes without inventing a feature/prerequisite corpus.

## Authoring and verification

The UI supports N tracks, catalog selection, copying/editing local classes, cumulative charts, automatic class skills with overrides, custom feature operations, equipment and attack profiles. Custom definitions travel with advancement in one snapshot; they cannot shadow imported IDs or aliases. Missing definitions, conflicting effects and invalid charts are errors.

Haste adds at most the intrinsic speed or 30 feet, before movement multipliers. Absent modes stay absent. Armor reduction is included in the intrinsic land speed used for that cap. Multipliers compose before min/max bounds.

Weapon enhancement participates in typed stacking. Positive Strength multipliers and full negative Strength penalties differ intentionally. Per-weapon full attacks expose BAB iteratives and eligible extras; indices travel through authoritative server recomputation. A resource safeguard rejects sequences over 256 rolls explicitly, without silently truncating them.

The hosted collaborative app uses local accounts and a shared character store. Its demo build still supports a level 1 fighter sample (elite array, Power Attack, Weapon Focus, Toughness, curated greatsword and chain shirt, one fighter advancement slot) and a multi-level showcase sheet; demo mode needs no backend and uses browser storage.

Tests cover aliases/duplicates, cross-track continuation, complete-track aggregation, twelve-track advancement, chart limits, class-skill union, custom effects unlock/undo, lifecycle creation/advancement proposals, HP/skill policy validation and explicit overrides, effect order, all sizes, armor/movement, enhancement stacking, condition composition, overflow, XP boundaries, failed/corrupt persistence, browser/hosted mode resolution and sample derivations, and browser plan parity. Browser tests use real forms and saved-state reloads. The checked-in TTS script executes in a dev-only Lua VM with mocked HTTP/UI/physical-die hosts: tests exercise weapon/strike selection, raw-face submission, empty-state refresh and an in-flight roll lock, but the TTS client is deferred and frozen at that scope, so it is not a parity target for new roll families (see the TTS gate in `docs/open-decisions.md`). CI checks builds, generated data freshness, browser persistence, the HTTP repository, and mocked hosted API load/save. The Site deployment and real TTS physics need separate smoke testing.

## Exact remaining frontier

1. **Class-skill source gaps:** the workbook has no matching Class Skills rows for Paizo Mystery Cultist or Paizo Sentinel. Their standard skill lists are now supplemented from the published Paizo entries: [Mystery Cultist](https://aonprd.com/PrestigeClassesDisplay.aspx?ItemName=Mystery+Cultist) and [Sentinel](https://aonprd.com/PrestigeClassesDisplay.aspx?ItemName=Sentinel). The unrelated third-party Sentinel remains separate. Consolidated-skill variants for these external supplements still need source-specific mappings.
2. **HP/skill allocation policy:** the lifecycle profile now turns each derived winning HD and skill-point chassis into an explicit HP-gain and rank-allocation decision, with source provenance, structured policy issues, and a deliberate override where the table permits one. Committed gains/ranks remain ordinary authored character facts; runtime damage is separate. The lifecycle wizard offers Average, Average (1st max), Average round up, Average round up (1st max), Maximum and Custom rolled HP policies. Constitution remains separately applied. Fractional-rank rules, cap calculation and 3.5 variants remain campaign policy.
3. **Contextual combat:** the roll/action-context and roll-outcome contract now exists. A roll names its actor, action, rolled fact and known defense; an action is modeled as a standard attack, a multi-weapon full attack with explicit per-weapon members, or a maneuver; every step carries its own resolvable plan with policy and effective threat range. Covered by tests: one shared Haste extra across weapons, touch eligibility (Deadly Aim vs rays), Rapid Shot inside ranged non-touch full attacks, Power Attack handedness, maneuver-conditional CMB and maneuver outcomes, natural secondary attacks, sight-based checks, automatic hit/miss, PF1e save naturals, threat ranges (20, 19–20, 18–20, widened and doubled), unresolved outcomes without a known defense, and deterministic resolution. Damage and initiative are planned through the same contract: each step carries the damage roll it deals (with a `criticalDamage` variant that applies the weapon's authored `criticalMultiplier`), and initiative is a plain d20 plan with no comparison. A plan declares its own primary check die, so a damage roll never inherits natural-face semantics. Improved Critical and Keen are expressible as a `double` expansion, scoped with `appliesWhen.attackIds`, and nonstacking by construction. Still authored rather than derived: precision-damage exemptions from the critical multiplier, automatic selection of the critical damage variant, combined two-weapon/natural/flurry sequence limits, proficiency, buckler hand use, cover and cover-dependent effects, denied Dexterity, jump-only penalties and action-economy restrictions. Do not concatenate single-weapon sequences into a combined full attack. Grants are reminders, not action enforcement. See `docs/open-decisions.md` for the maneuver, critical-damage, caller-supplied-defense and multi-source extra-attack questions this leaves open.
4. **Equipment composition/inventory:** character-owned identity, currency, item quantities, carried state, weights, values, slots, compatible numeric armor/shield material adjustments, containers, companion inventory and basic carrying capacity/encumbrance are represented. Material special-note rules, armor attachments, slot legality, damage resizing, item catalog completeness and all source container rules still need item-specific composition data.
5. **Large class systems:** 27 standard casting tables now seed prepared/spontaneous sources, with class-level slots/known progressions, bonus slots, at-will cantrips, caster level, concentration, DCs and sourced spell damage. Nine Psionics and 17 FFd20 profiles import resource capacity, available tiers and known progressions. The workbook provides generic formulas for Spheres, Veilweaving and maneuvers. Character-owned entries now support authored damage/healing dice, caster-level scaling and per-use resource costs; named spell/power/technique corpora and automated turn rules remain unmodeled. Spell casts roll target saves from entered save bonuses against the derived DC, check caster level against entered spell resistance, resolve negates and half damage, and compare touch attacks against entered touch AC. Partial/disbelief save results still require their spell-specific text; components are displayed, while buff duration and action economy are not enforced. Flurry substitutions, kineticist profiles, feature prerequisites and feats still need mapping. Prestige source selection uses lifecycle choices when a progression declares the linked feature requirement.

The roll-context, outcome, damage/initiative plan and check-die contracts are now implemented, including PF1e save naturals, authored critical multipliers and threat-range expansion (Improved Critical/Keen doubling with weapon scoping and nonstacking). A campaign character profile now makes advancement topology, HP/skill allocation, available progression sources, and permitted overrides explicit; it does not settle every PF1e-versus-3.5/3.PF option or combat variant. The remaining large models are spellcasting/feature resources and precision damage. This pass adds neither runtime LLM interpretation nor optimization/feat automation. Improved Critical itself stays authored per character because the feat must name a weapon, which curated content cannot choose for the player; `appliesWhen.attackIds` is how that choice is recorded.
